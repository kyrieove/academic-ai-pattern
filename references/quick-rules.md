# AI-pattern 快速规则卡

本文件是默认快速审查的操作规则。候选由脚本高召回扫出，本卡管的是**怎么裁决**：哪些判为问题，哪些受保护。争议裁决或深度审查再读取 `../ai_pattern.md`。

## 入口

对每条候选先问：**这段文本缺少了什么可观察的信息或论证关系？**

必须指明缺少的定义、推理环节、证据、必要区分，或重复承担的段落功能。M1–M6 是解释标签，不证明作者没有思考，更不证明文本由 AI 生成。关键词和标点只能定位，不能定罪。

脚本只扫描已实现的形式信号；通读时发现的语义问题也进入候选账，记录原文区块与发现理由。尤其是 S3、S6、S7、S10、S11、S14，不能以脚本零命中代替语义审查。

## 六个机制

| 机制 | 省掉的成本 | 规则 |
|---|---|---|
| M1 穷举代替取舍 | 决定删什么 | S1、S2、S13 |
| M2 抽象代替机制 | 把推理算完 | S3、S4 |
| M3 替读者评价 | 信任读者 | S8、S13、S15 |
| M4 默认动作反复调用 | 记得自己写过什么 | S4、S5、S6、S10 |
| M5 顺序只服从作者 | 判断读者此刻知道什么 | S7、S13、S16 |
| M6 句式和声势代替证据 | 让主张与证据对齐 | S9、S11、S12、S13、S14 |

## S1–S16

| 规则 | 触发机制 | 快速判定 | 主要保护条件 |
|---|---|---|---|
| S1 连续动词组／列表堆叠 | 多项只表示“很多”，没有形成取舍 | 删除项目后事实、研究设计和论证对象是否仍完整？ | 样本组、数值比较、实测结果、必要分类；删除会改变研究事实 |
| S2 理由枚举式 | 用 N 个弱理由代替一条论证 | 去掉编号后是否还有推进关系？ | 每个理由独立改变结论 |
| S3 抽象到不知所言 | 未定义区分、空定义、浅层 payoff | 谁依据什么推出什么？ | 相邻句已给出施事、来源和推理 |
| S4 冒号＋展开 | 反复“抽象断言：具体展开” | 具体内容能否直接作主语？ | 真正的定义、清单或一次性强调 |
| S5 指代滥用 that | 对当前对象无故拉远 | 指代对象是否仍在当前焦点？ | that-从句、时间指代；仅同作者确认后使用 |
| S6 表述／功能槽重复 | 同一说法或同一段落动作反复出现 | 重复是否功能冗余？ | 术语一致、Methods 体裁、研究问题回扣 |
| S7 衔接断裂 | 段首未承接上段留下的问题 | 只读段末和下段首句能否连起来？ | 标题或明确逻辑关系已完成承接 |
| S8 评价式句子 | important/useful/novel 等替读者判断 | 删除评价后命题是否不变？比较维度是否已由全文建立？ | `strongest/clearest` 准确压缩已建立的跨研究证据排序 |
| S9 无根据对立／幽灵反驳 | not X but Y、rather than 等无来源 | X、Y 是否都有正文或文献支撑？ | 真实理论竞争、条件比较、必要范围否定 |
| S10 术语身份漂移 | 同一构念轮换近义词 | 是否改变测量或理论身份？ | 构念本来不同、被引来源的标准用词 |
| S11 认识强度失配 | 动词、方向、范围超过证据 | 逐项对账对象、方向、条件、强度 | 与设计绑定的必要对冲 |
| S12 模糊归因／引用堆叠 | studies show、句末堆引但来源不清 | 谁用什么设计支持哪条主张？各来源是分别支持不同项目，还是共同支持一个综合判断？ | 多来源共同支持同一综合判断；Methods 被动 |
| S13 模板支架 | 可移植开头、结尾、贡献或未来工作 | 换掉变量名后是否仍原样成立？ | 写出本文特有后果；thesis 必要 roadmap |
| S14 造作比喻 | 抽象物被赋予戏剧动作或金句 | 字面关系是否更准确？ | 领域稳定隐喻和标准技术术语 |
| S15 修辞问句／自问自答 | 临时提问后自己回答 | 问题此前是否已立过？ | 标题回扣、研究问题、刺激材料 |
| S16 机械导航／元话语 | 路标没有新增关系或边界 | 删除后信息是否完全不减？ | 长篇 thesis roadmap、必要交叉引用 |

## 裁决

候选进来之后逐条判，**每条都要写下理由**。产出分两档，不要跳档：

1. **独立裁决**（默认）：结构化 JSON 账中每个候选有一条 decision（见 report-schema）。需要 Markdown 展示时渲染为 `编号 | 形状／子型 | 理由 | 裁决`。所有候选都要有记录。
2. **完整 finding**：`需修改` 必须展开；需要作者行动的 `待作者判断`、`核查未完成` 也可展开。其他候选留在账中。按 report-schema 的字段展开。

```
S1-014 | 名词组 | 四组设计，删任一组改变研究事实 | 受保护
S1-022 | 名词组 | 四种模态后文没分别用上 | 需修改
S1-031 | 动词组 | choose between strategies 后文不再出现 | 需修改
```

**先找保护理由，找到就停。** 对每条先问"有没有理由留"，而不是"有没有问题"。保护理由通常一眼可见——这是四组样本、这是实测结果、这是被引研究的标准用词。手册里采纳率低的规则，默认处置是不动。

加载了 `corpus/BASELINE.md` 时，保护理由多两条，都必须写明依据的条目与篇数：`作者基线（N/M 篇同 section 如此）`、`领域基线（N/M 篇同 section 如此）`。写不出篇数就不是基线证据，按无基线处理。

**理由必须落到这一句的内容。** 写成"删掉 X 之后 Y 会丢"或"删掉 X 之后什么都不丢"，X 和 Y 都要具体。"列表过长""三项结构""表达冗余"不是理由；写不出具体的 X 和 Y 就是没判，只能记 `待作者判断`，不能记 `需修改`。

**同一条理由不能覆盖多条候选。** 一条通用理由判 N 条，等于一条都没判。

## 候选改法守恒

候选改法是本 skill 唯一产出新文本的地方，"源稿只读"的边界保护不到它。

**每项事实、条件和论证关系都要能在触发片段或其所在区块指出依据。** 允许语法变换、词形变化与等义表达；不要求逐词复用。无法支持的具体机制或事实必须撤销，改为请作者补充，不能靠概括掩盖新增。

**一律不得新增**：人名、机构、地名、数字、比例、单位、样本量、日期、时间顺序、引语、引用来源、因果或动机。原文写 `improved performance`，不得改成 `improved accuracy by 12%`——哪怕 12% 出现在别的段落。

**一律不得删除**：限定词与让步（`may`、`might`、`could`、`suggest`、`appear`、`likely`、`in some cases`、`under these conditions`）、条件从句、范围限定、证据等级标记。把 `may improve` 改成 `improves` 是篡改认识强度，不是去 AI 模式。

**S11 是唯一例外**：S11 的裁决对象本来就是强度失配，改法可以上调或下调强度，但必须在 `**守恒核对**` 里写明依据稿内哪一句证据，不得默认删除对冲。

**每条带候选改法的 finding 必须写 `**守恒核对**` 字段**：一句话说明改法保持了哪些对象、方向、数量、范围、来源和证据等级；改动其中任何一项时写明依据。

## 三类发现必须分开

1. **AI 模式**：S1–S16 的机制成立，ID 用 `AP-Sxx-xxx`。
2. **内容硬错误**：内部方向冲突、数字／引用／对象不一致，不要伪装成文风；ID 用 `AP-H-xxx`。
3. **方法学风险**：设计或分析不足以支持结论，例如从单次观察性相关推导因果机制；ID 用 `AP-M-xxx`。

同一个问题只建一个主 finding；其他相关规则写入“交叉规则”，不要重复引用与展开。

## 作者模型

- A 类通用约束始终使用：不造事实、不改方向、数字、范围、来源和证据等级。
- B 类学科惯例始终使用：术语一致、引用对应、Methods 体裁保护。
- C 类个人指纹只有在用户确认同一作者，或明确要求使用 §11 个人模型时，才能单独产生 `需修改`。
- 未确认同一作者时，S5 及其他纯个人偏好最多标 `待作者判断`，并写 `作者模型不足`。

## 快速审查优先级

1. 内部矛盾、数字、引文和 claim–evidence fit。
2. 推理缺口、术语身份和段落顺序。
3. 空支架、虚假对立、无内容评价。
4. 局部措辞与节奏。

默认只展开高置信、可行动的候选。低风险形式命中在保护测试后归零或合并，不为凑数进入报告。

## 惯例查询：先查本地语料

判"这个说法是不是本领域惯例"时（S14 自造比喻 vs 领域死喻、S10 术语身份、S3／S13 支架措辞、S11 措辞强度），**先查本地语料，不要凭印象**。查询顺序，命中就停：

1. `corpus/BASELINE.md` —— 存在且适用范围覆盖本稿 section 与设计时；
2. `corpus/field/raw/` 的同 section 原文，按下面的选取方法取 5 篇；
3. 联网核查，边界见「联网边界」。

没有 `corpus/` 时从第 3 级开始。**这是默认状态，不影响任何裁决的可用性**——基线是加分项，不是前置条件。基线里查不到某个说法，只让保护测试未通过，不得据此把候选判为 `需修改`。

```bash
python scripts/scan_all_candidates.py extract.json --markdown ledger.md
```

可配合领域文献库或 Europe PMC 等权威公开数据库检索常规用法。**判据是定性的，不设百分比门槛**：

- **一篇都没有** → 未找到惯例证据；不能据此断言自造或未定义。只有稿内语义缺陷独立成立时才可判问题，否则记 `待作者判断`；访问失败记 `核查未完成`。
- **有，但只出现在与稿件不同体裁的文献里**（实证研究的 Methods、supplementary），而同体裁的叙述性综述不这么写 → 不能当本文的惯例依据，最多 `待作者判断`。
- **同体裁文献里作为常规表述反复出现** → 受保护。判"常规"要点开几篇看上下文，确认是同一个意思，不是同形不同义。

**"点开几篇"的选取方法**——不按这个选，就等于没查：

1. 按 **section（Introduction／Methods／Results／Discussion）＋ 研究设计（实验／观察／综述／meta）** 筛出同类文献；
2. 匹配项超过 5 篇时，取近 5 年、期刊层级与目标期刊相当的 5 篇；
3. 匹配项不足 5 篇时，用同 section 不同主题的文献补齐到 5 篇，并在报告的「外部证据」里写明补齐来源；
4. 读的目的不是数命中，是确认这 5 篇里该表述承担的是同一个语义功能。说不出这 5 篇的共同用法，记 `核查未完成`，不得记 `受保护`。

命中数写进报告作证据（如 `48/384`），但它是**给人看的线索，不是判定门槛**——不要用比例卡线代替读上下文。

语料只证明"领域里有人这么用"，不证明"这里这么用是对的"——同联网核查的规矩。查不到再联网。

## 联网边界

快速模式仅在**裁决依赖外部事实**时联网：

- 术语是否为领域稳定用法；
- 引用是否支持具体主张；
- 首创性、方向、样本、任务或方法细节；
- 候选改法需要验证学科搭配。

纯结构、重复、评价、导航和删除测试默认本地裁决。搜索命中只能证明存在，不能证明语义适配。访问失败时使用 `核查未完成`，不要扩大检索。

## 不追的信号

单个高频词、三项结构、长句、分号、被动语态、名词化、第一人称、破折号、冒号、`may`、`however`、非人主语和低 n-gram 频率都不能单独构成 finding。不得使用检测器分数、固定节奏配额、随机同义替换或故意错误。
