# academic-ai-pattern

[English](README.md) | 简体中文

**定位论文中的表达与论证问题，给出有依据、可追溯的修改建议。**

`academic-ai-pattern` 将六大机制、十六类规则与稿件上下文结合，用于审查英文学术论文。报告说明问题在哪里、为什么需要处理、哪些信息必须保留，并列出具体修改方向。作者据此逐项修订，保留对原稿的编辑权。

## 主要优点

| 优点 | 项目如何实现 | 对作者的价值 |
|---|---|---|
| **从句子表面进入论证结构** | M1–M6 与 S1–S16 共同检查冗余列举、抽象表述、重复功能、段落衔接及证据失配 | 既检查局部措辞，也指出定义、推理和证据之间缺少的联系 |
| **按学术功能判断表达** | 对实验条件、结果清单、术语重复、Methods 程序语言和必要对冲逐项做保护测试 | 修改有明确的保留依据，避免把必要信息当作风格问题处理 |
| **建议直接对应原文** | 每项发现列出原文位置、触发片段、理由与处理方向；有充分依据时附候选改法 | 打开报告即可定位需要处理的段落，知道改哪里、为什么改、怎么改 |
| **审查过程可复核** | 保留原始候选和逐条裁决，披露已审查范围；脚本核对源文件、候选清单与报告对应关系 | 能查清哪些内容已经判断、哪些仍待核查，并对具体裁决提出修正 |
| **保留作者的表达选择** | 源稿只读，建议单独输出；通过作者配置声明拼写、引用形式等个人偏好 | 按自己的研究目的和写作习惯采纳建议，独立决定原稿修改 |
| **将阅读积累转为可复用基线** | 按章节和研究设计蒸馏作者或领域语料，记录逐篇指标与写作特征，生成 PROFILE 和 BASELINE | 同一批语料用于后续稿件审查、作者风格参照和期刊写法比较 |

从下面的六组示例可以直接查看各类问题的判定方式；[完整的聚焦审查示例](examples/sample_report.md)展示了报告与裁决账如何对应。

项目名称中的“AI pattern”沿用规则手册的命名。这些规则用于检查学术表达中的具体问题；命中规则不构成 AI 生成来源的证据。项目不提供 AI 生成概率或检测器分数。

## 适用范围

本项目主要面向英文实证研究论文及学位论文。综述和其他学术体裁可在明确审查范围后使用，但相关判断仍需结合体裁与学科惯例。

审查流程要求保持源稿只读，将发现和候选改法写入独立文件。需要修改时，由作者根据报告复核并处理原稿。样本组、测量指标、统计结果、必要限定和专业术语应按其实际学术功能判断，不能仅因列表、重复或特定句式而删除。

本项目包含两个入口：

| 入口 | 任务 | 主要产物 |
|---|---|---|
| 稿件审查 | 定位候选问题，检查上下文，并记录逐条裁决 | Markdown 报告、候选 JSON、裁决账 JSON |
| 语料蒸馏 | 从作者或领域语料归纳写作特征及其适用范围 | `DNA/PROFILE.md`、分层观察和 `corpus/BASELINE.md` |

两者可独立使用。没有语料基线时，稿件审查仍可运行。

## 使用方法

### 在 Agent 中使用

获取仓库后，按所用 Agent 环境的 skill 配置方式加载整个目录，并保留 `scripts/`、`references/` 和 `assets/` 等配套文件。入口说明见 [SKILL.md](SKILL.md)。具体的安装路径和调用语法由运行环境决定。

```bash
git clone https://github.com/kyrieove/academic-ai-pattern.git
```

加载 skill 后，可使用以下请求：

```text
使用 academic-ai-pattern 审查 manuscript.docx，生成审查报告。
```

默认采用快速审查。需要更详细的裁决过程或限定范围时，可明确指定：

```text
对 manuscript.docx 进行深度审查，展开逐项判定依据。
仅审查 manuscript.docx 的 Discussion，重点检查 S10 和 S11。
```

快速与深度模式都要求记录范围内的候选裁决；深度模式增加上下文引文和判定过程。聚焦模式将范围外的规则标为“未审查”。

### 运行配套脚本

脚本用于提取、形式扫描和报告一致性检查。语义判断、裁决理由及报告内容由 Agent 或审查者完成；仅运行扫描器不会得到完整审查。

建议使用 Python 3.10 或更高版本。DOCX、Markdown 和 TXT 提取使用 Python 标准库；PDF 提取另需 `pypdf` 或 `PyPDF2`。PDF 提取结果须对照原页面核对版面与段落边界；内置提取器不执行 OCR。DOCX 提取也有范围限制，例如不提取页眉、页脚、批注和文本框；警告应随报告披露。

以下命令从仓库根目录运行，用于复现随附的 S1/S13 聚焦示例。先将 `<TMP_DIR>` 替换为已创建的临时目录路径；路径包含空格时保留引号。

```bash
python -X utf8 scripts/extract_document.py examples/sample_paper.md --output "<TMP_DIR>/extract.json"
python -X utf8 scripts/scan_all_candidates.py "<TMP_DIR>/extract.json" --rules S1 S13 --output "<TMP_DIR>/candidates.json"
python -X utf8 scripts/validate_report.py examples/sample_report.md "<TMP_DIR>/extract.json" --source examples/sample_paper.md --candidates "<TMP_DIR>/candidates.json" --ledger examples/sample_ledger.json
```

该例使用仓库已有的报告和裁决账。审查新稿件时，须先依据新候选集完成裁决与报告，再运行验证器。候选 ID 或源文件内容变化后，应重新生成相应产物。

## 审查方法

1. **提取与分区。** 提取文本区块，记录源文件 SHA-256、位置和提取警告，核对实际扫描范围。
2. **建立稿内参照。** 确认研究对象、主要主张、术语、方向、条件和证据层级。
3. **生成候选。** 脚本定位已实现的形式信号；通读补充术语身份、推理关系等语义候选。脚本零命中不等于该规则已完成审查。
4. **逐条裁决。** 检查候选是否承担必要的学术功能，说明可观察的缺口或保留依据；外部事实影响裁决时，再进行来源核查。
5. **报告与复核。** 输出报告和裁决账，运行一致性检查，并另行复核候选改法是否保留原有事实、范围与证据强度。

## 六大机制（M1–M6）

六大机制构成本项目的分析框架，分别对应学术写作中的取舍、推理、评价、重复控制、读者视角和证据约束。M1–M6 解释问题如何体现在文本中，S1–S16 则用于定位和记录具体表现。

### M1 穷举代替取舍

**写作任务：决定保留什么、删除什么。** 多项动词、理由或未来方向逐一铺开，却没有说明各项如何推进论证。审查时检查每一项的独立作用，区分必要清单与冗余列举。

对应规则：S1、S2、S13。

### M2 抽象代替机制

**写作任务：把推理过程写清楚。** 用抽象概念或概括性结论替代具体关系，例如只写 `plays a crucial role in`，却没有交代作用对象、条件和推理依据。审查时明确谁依据什么，经过哪一步，推出什么结论。

对应规则：S3、S4。

### M3 替读者做评价

**写作任务：呈现判断依据，让读者据此评价。** 用 `important`、`crucial`、`fascinating` 等评价词替代对研究意义的说明。审查时检查评价是否建立在明确的比较维度或证据排序上；没有增加信息的评价予以精简。

对应规则：S8、S13、S15。

### M4 默认动作反复调用

**写作任务：记住前文已经完成的表达与论证。** 反复使用同一开头、冒号展开或段落收束方式，重复承担已经完成的论证功能；同一构念的近义词轮换也在此类审查中处理。判断依据是功能冗余与身份漂移，必要的术语重复保留。

对应规则：S4、S5、S6、S10。

### M5 顺序只服从作者

**写作任务：判断读者此刻已经知道什么。** 段落按照作者的材料顺序排列，却没有承接前文已经建立的问题、对象或关系。审查时核对段末与下一段开头的联系，并检查导航语是否交代了真实的论证推进。

对应规则：S7、S13、S16。

### M6 句式声势代替证据

**写作任务：让主张与证据对齐。** 借助对立结构、强化断言、模糊归因或修辞性比喻推进结论，却没有给出相应支持。审查时逐项核对对象、方向、条件和证据强度；对冲的增删同样服从这一要求。

对应规则：S9、S11、S12、S13、S14。

六大机制用于解释和裁决文本问题，不用于鉴定作者身份或真实生成来源。

## S1–S16 规则范围

| 规则 | 审查对象 | 判断时需保留的区分 |
|---|---|---|
| S1 | 连续动词与列表堆叠 | 冗余列举与必要的条件、步骤或结果清单 |
| S2 | 枚举式理由 | 形式编号与各自成立的独立理由 |
| S3 | 抽象表述 | 信息缺失与上下文已定义的概念 |
| S4 | 冒号展开 | 重复支架与明确的定义或清单 |
| S5 | 指示词 `that` 的使用 | 已确认的个人偏好与一般语法用法 |
| S6 | 表述或段落功能重复 | 功能冗余与术语一致、必要回扣 |
| S7 | 段落衔接 | 推理断裂与标题或上下文已建立的关系 |
| S8 | 评价式表述 | 无依据评价与有明确维度的证据比较 |
| S9 | 对立与否定结构 | 无依据对立与真实理论竞争、范围限定 |
| S10 | 术语身份 | 同一构念的名称漂移与不同测量对象 |
| S11 | 主张的认识强度 | 超出证据的断言与必要的不确定性表达 |
| S12 | 归因与引用组合 | 来源不清与多来源支持同一综合判断 |
| S13 | 模板化论证支架 | 可移植的空泛表述与本文特有的论证功能 |
| S14 | 比喻表述 | 关系不明的修辞与领域通行术语 |
| S15 | 提问与自问自答 | 无实质推进的设问与正式研究问题 |
| S16 | 导航与元话语 | 冗余路标与必要的篇章导引 |

操作规则见 [quick-rules.md](references/quick-rules.md)，详细讨论见 [ai_pattern.md](ai_pattern.md)。这些类别并非经过跨学科验证的诊断量表。规则命中数表示待复核的候选数量，不代表稿件质量或检测准确率。

## 六组审查示例

以下为虚构教学片段，分别展示列表、冒号、评价、比喻、术语和对冲的审查方式。每例列出原文、裁决依据及处理动作。

### 1. S1 连续动名词与列表堆叠

**原文：**

> Evaluating the autonomous control pipeline requires calibrating visual sensor feeds, synchronizing telemetry data packets, computing steering vectors, and validating fail-safe triggers.

**裁决：待作者判断。** 原句列出传感器校准、遥测同步、转向计算和失效保护验证四项步骤。单凭四个动名词，无法认定其中任何一步冗余。位于引言也不构成删除技术事实的依据。

**处理动作：** 对照研究设计和上下文，逐项核对其论证功能。确认重复的步骤后再精简；承担独立功能的步骤保留。

**守恒核对：** 不引入原文没有说明的 control stability、tracking accuracy 或因果关系。

### 2. S4 冒号与展开

**原文：**

> The architecture expects the following: packet loss, asynchronous node updates, and variable network latency.

**裁决：受保护。** 冒号引出三项明确的运行条件，承担清单展开功能。该句没有显示重复的空泛支架。

**处理动作：** 保留原句。判断全文是否反复使用同一支架时，另查各处是否承担重复的论证功能。

**守恒核对：** 保留 packet loss、asynchronous node updates 和 variable network latency 三项条件。

### 3. S8 无依据的评价

**修改前：**

> The algorithm reduced response latency in this sample. These results are fascinating.

**裁决：需修改。** 第一句报告结果及其适用范围；第二句只表达赞赏，没有增加事实、比较维度或推理。

**候选改法：**

> The algorithm reduced response latency in this sample.

**守恒核对：** 保留算法、响应延迟的变化方向及 in this sample 的范围限定；不增加样本量、效应量或作用机制。

### 4. S14 比喻替代具体关系

**原文：**

> The attention mechanism acts as an omniscient digital conductor, furiously orchestrating the chaotic symphony of multi-source sensory tokens.

**裁决：需修改。** conductor 和 symphony 描绘了形象，却没有说明 attention mechanism 如何处理 sensory tokens。

**处理动作：** 请作者依据实际方法写明处理对象、操作及其关系。该句没有提供足以支持具体替代句的方法信息。

**守恒核对：** 不补入 dynamic weight matrices、high-saliency embeddings 等原文没有交代的机制。领域通行的技术隐喻另按其定义和用法判断。

### 5. S10 术语身份与近义表达

**原文：**

> The benchmark evaluated response latency. Processing delay was measured separately.

**裁决：受保护。** separately 明确区分了两项测量；不能因为 latency 和 delay 词义接近就统一名称。

**处理动作：** 保留两项测量的名称。若其他段落交替使用 response latency、processing delay 和 execution lag，则对照各自的操作定义：同一指标统一名称，不同指标保留区别。

**守恒核对：** 术语统一依据测量身份，不依据词频或表面相似性。

### 6. S11 层叠对冲与主张强度

**原文：**

> Although our evaluation is restricted to synthetic benchmarks, our findings might tentatively suggest that adaptive scheduling could potentially mitigate transient queue congestion.

**裁决：待作者判断。** 句中叠加了多层对冲，但没有给出判断证据强度所需的设计与结果。synthetic benchmarks 则明确限定了研究范围。

**处理动作：** 对照研究设计、实测结果和不确定性依据，确定主张强度后再精简对冲。保留研究范围，以及证据要求的限定。

**守恒核对：** 不新增节点数、百分比、p 值或机制；不将限定于 synthetic benchmarks 的结论改成一般性断言。

完整的稿件审查示例见 [sample_report.md](examples/sample_report.md)，逐条裁决见 [sample_ledger.json](examples/sample_ledger.json)。

## 报告与裁决

报告将文体与论证模式（`AP-Sxx`）、稿内事实冲突（`AP-H`）和方法学风险（`AP-M`）分开记录。每条候选使用以下一种裁决：

| 裁决 | 含义 |
|---|---|
| 需修改 | 存在已说明的文本缺陷，条目列出依据与处理方向 |
| 待作者判断 | 上下文、作者意图或偏好不足以支持确定裁决 |
| 受保护 | 该形式在当前语境中承担必要的学术功能，保留原文 |
| 核查未完成 | 裁决所需的来源或事实尚未完成核对 |

“受保护”针对当前候选的表达功能，不意味着相关数据、引文或方法已通过全面核验。所有修改建议仍需作者复核。

文件输入的主要产物如下；已有同名文件时选择新的版本号。

| 文件 | 内容 |
|---|---|
| `<stem>-ai-pattern-report.md` | 范围、覆盖表、行动清单、发现与限制 |
| `<stem>-ai-pattern-candidates.json` | 原始脚本候选、位置、计数与扫描范围 |
| `<stem>-ai-pattern-ledger.json` | 逐条裁决、语义补充候选及 finding 对应关系 |

候选改法仅可附于“需修改”条目，并须说明事实与论证关系的保留情况。原文依据不足时，列明需要作者补充的信息。

输出格式见 [report-schema.md](references/report-schema.md)。[示例报告](examples/sample_report.md)及其[裁决账](examples/sample_ledger.json)使用虚构教学稿件，展示八条候选的 S1/S13 聚焦审查；示例中的引用未经过真实性核验。

## 作者偏好与语料基线

[作者配置模板](author_profile.template.yaml)用于声明拼写、引用形式等个人偏好。个人偏好需经用户确认后使用，不能覆盖事实、构念身份和证据强度的约束。

语料蒸馏由用户明确请求后启动，流程见 [distill.md](references/distill.md)。L1 脚本按索引中的章节和研究设计选取语料，逐篇计算语言指标并汇总；结构、证据策略与论证关系仍需通读归纳。

`DNA/PROFILE.md` 保存写作特征与适用范围；`corpus/BASELINE.md` 保存可追溯至具体篇目的保护证据。语料中的用例证明该用法在所引篇目中出现，但不能单独证明它在当前稿件中合理；未检索到用例也不能单独证明表达有误。

基线校准要求使用独立标注，同时检查合法表达的误伤和真实问题的漏检。仅观察“需修改”数量减少，不足以确认基线有效。

## 验证与局限

仓库提供针对提取、候选与裁决对应、数值检查及语料筛选的回归测试：

```bash
python -m unittest discover -s tests -v
```

验证器检查报告格式、源文件校验值、引文位置和账本一致性，并通过重新扫描核对原始候选。测试通过表明这些已测试行为符合预期，不证明语义判断正确。

目前仓库未提供独立人工标注的跨学科评测结果，因此无法据此报告准确率、召回率或误伤率。实际裁决会受到所用模型、上下文长度、提取质量、学科知识和来源可访问性的影响。候选改法须与原文逐项核对限定条件和论证关系。

本项目适合作为作者自查和审读记录工具；其输出不能作为 AI 来源鉴定、研究有效性认定或期刊录用结果的依据。
